# Changelog

Changes of the `anpassungen` branch on top of the official Solakon ONE integration
([solakon-de/solakon-one-homeassistant](https://github.com/solakon-de/solakon-one-homeassistant)).
Each release is named `<upstream version>-anpassungen.<n>`; `manifest.json` keeps the
upstream version. Changes of the upstream integration itself are not listed here.
Issue, PR and discussion numbers refer to the upstream repository.
Format based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

Open upstream PRs #326, #327 and #328 on top of 1.8.0-anpassungen.2.

### Changed
- **Write errors reach the caller (#326):** A write that the device rejects, or that is attempted without a connection, makes the action (`number.set_value`, `select.select_option`) fail with a translated error instead of only logging `Failed to set …`. Automations without `continue_on_error` stop there. The log shows the register address and the Modbus response. All entities write through one path, `SolakonModbusHub.async_write_value`, which encodes the value from its register definition and rejects values that do not fit the register instead of clamping them (`modbus.py`, `number.py`, `select.py`, `translations/`).
- **Read failures (#327):** A poll fails when none of the regular register batches could be read; before, the static values made every poll count as successful. Values read once per minute are dropped when their last successful read is older than 180 s. Number and select entities without a value are unavailable, like sensors (`modbus.py`, `exceptions.py`, `number.py`, `select.py`).

### Fixed
- **Connection after a failed setup (#328):** The Modbus client is closed before setup is retried; before, every retry left a client reconnecting in the background (`__init__.py`).
- **Device info (#328):** Model and serial number come from the static registers instead of four extra reads during setup. Cleanup without behaviour change: bitfield type comparison, one `format_version` helper for the version sensors, `REMOTE_CONTROL_MODE_SELECT_ENTITY_DESCRIPTION` spelling, dead code removed.

## [1.8.0-anpassungen.2] – 2026-11-02

Based on upstream 1.8.0.

### Changed
- **Daily AC counters:** Registers 39623 and 39627 sit in the same block as the lifetime counters 39621 and 39625 and count at the AC connection of the device as well. They are now named AC output/input energy today instead of grid export/import energy today. Entity IDs of existing installations stay unchanged (`translations/`, README).

### Fixed
- Type check of the counter guard test: the `async_write_ha_state` stub is cast for mypy (`tests/test_counter_guard.py`). No change to the integration.

## [1.8.0-anpassungen.1] – 2026-11-02

Based on upstream 1.8.0. PRs #266, #288, #292, #303 and #307 from 1.7.0-anpassungen.1 are part of upstream 1.8.0; #294 was closed upstream as superseded.

### Changed
- **Entity names:** Sensor `remote_timeout_countdown` is called "Fernsteuerung Restzeit" in German instead of a second "Fernsteuerung Zeitüberschreitung" (discussions #210, #202). `grid_total_export/import_energy` are called AC output/input energy, as the counters measure at the AC connection of the device (discussion #277). `bms1_ambient_temp` is called BMS temperature (discussions #139, #102). Entity IDs stay unchanged.
- README: order of steps for remote control, current entity IDs, English/German entity table generated by `scripts/entity_table.py` including meter, EPS and daily energy sensors.

### Removed
- **800 W discharge limit from #302:** Upstream 1.8.0 caps `remote_active_power` and `grid_export_power_limit` at 800 W and rejects higher values in discharge modes. This also blocks charging above 800 W and EPS output above 800 W (#321, #322, #324). The limit is a pure software check of the integration; `power_limit.py` and its checks are removed, the device range up to 1200 W applies again. The pytest setup from #302 stays.

### Fixed
- **Options flow on Home Assistant 2025.7:** `OptionsFlowWithReload` only exists from Home Assistant 2025.8, while `hacs.json` allows 2025.7. The options flow now uses `OptionsFlow` plus an update listener (`config_flow.py`, `__init__.py`).
- **`operating_mode` with unknown register values:** Options are strings, unknown values map to `None`; Home Assistant raised `ValueError` for values outside the options (`sensor.py`).
- **Type check in CI:** mypy ran outside the project environment, so all Home Assistant types were `Any` and type errors stayed hidden. It now runs with `uv run mypy .`; the reported errors are fixed (`.github/workflows/type.yaml`).

## [1.7.0-anpassungen.1] – 2026-10-04

Based on upstream 1.7.0, plus the open upstream PRs #266 (unused register definitions), #288 (reconfigure step for host, port and device ID), #292 (remote control sensor value 8), #294 (CI tooling), #303 (battery Energy Dashboard docs) and #307 (batched register reads).

### Changed
- **Register reads (#307):** 5 instead of 16 batches per poll. Gaps inside the address spans 39053–39152 and 39201–39286 are bridged, energy counters, BMS values, `operating_mode` and `network_status` are read at most every 60 s, `grid_standard_code` and firmware versions once per connection, and registers of disabled sensors are skipped. Measured with a 1 s scan interval: 319 ms per poll before, 99 ms after.
- **Entity names:** as in 1.8.0-anpassungen.1.

### Removed
- **800 W discharge limit from #302:** as in 1.8.0-anpassungen.1.

### Fixed
- Type errors hidden by mypy, as in 1.8.0-anpassungen.1.
